# 🚂 CRTicketMonitor 12306余票查询与监控助手

[![Python Version](https://img.shields.io/badge/python-3.14+-blue.svg)](https://www.python.org/) [![License](https://img.shields.io/badge/license-MIT-green.svg)](https://opensource.org/licenses/MIT)

这是一个轻量级的12306余票查询与监控工具，使用AI辅助进行开发。该工具目前尚在完善之中，作者代码水平不高，学习的时间较长，遇到问题还请多多见谅！

---

## 一、核心功能

### （一）基础功能

* **席位覆盖**：支持商务座、一等座、二等座、软座、卧铺等常用席位查询；
* **车站同步**：自动从12306官方实时抓取最新的车站代码映射表；
* **异常自动纠错**：查询时若输入了本地未记录的车站，程序会自动触发二次同步，确保查询成功；
* **双模式监控**：
  * **自动模式 (Auto)**：自定义随机间隔刷新，适合长时间挂机监控；
  * **手动模式 (Manual)**：按需手动刷新，灵活掌握查询节奏；
* **高亮视觉提醒**：查询到有票的车次时，车次编号将以**绿色**显著标出；
* **及时通知**：当发现有票的车次时将进行筛选，在下一次刷新时进行对比，实现**强提醒**（该功能部分杀毒软件可能会提示，选择允许即可）

## 二、快速开始

### （一）环境准备

在运行此程序之前，你需要安装以下依赖库：

## 三、操作指南

### （一）一级菜单 (启动后)

```
启动主菜单
-----------------------------------------------------------------
1. 开始新的查询
2. 修改默认配置
3. 查看查询历史
4. 通知设置
5. 退出程序
-----------------------------------------------------------------
```

**操作说明**:
- `1`: 进入12306余票查询界面
- `2`: 修改DC识别模式、通知冷却时间等配置
- `3`: 查看历史查询记录和统计信息
- `4`: 配置通知渠道（Windows/企业微信/飞书/钉钉）
   > 目前对windows的适配已经做了，但是剩下几个只留了一个接口，并没有对剩下的软件进行测试，不保证能够接入，后续有时间了会学习相关知识
- `5`: 退出程序

### （二）查询界面操作

进入查询后，显示车次列表，底部有操作提示：

```
[F]筛选排序  [M]切换模式  [E]导出结果  [R]重新查询  [Q]退出
```

**操作说明**:
- `F`: 按 `F` 键进入二级筛选/排序菜单
- `M`: 切换D/C低号段的识别模式（官方模式/智能模式）
- `E`: 导出查询结果到JSON文件
- `R`: 重新开始查询
- `Q`: 退出程序
- `Enter`: 立即刷新一次

### （三）二级筛选/排序菜单

按 `F` 键进入后，显示如下菜单：

```
筛选与排序菜单
================================================================
[当前筛选]
  车型: 全部 | 始发: 全部 | 到达: 全部
  时段: 全部时段 | 排序: 无
----------------------------------------------------------------
[车型筛选]  1.全部  2.高铁动车  3.普通车
[站点筛选]  4.始发站  5.到达站
[时段筛选]  6.全部时段  7.00:00-06:00  8.06:00-12:00  9.12:00-18:00  0.18:00-24:00
[排序选项]  A.最早发车  B.最晚发车  C.最早到达  D.最晚到达  E.最短历时  F.最长历时
[其他]      R.重置筛选  X.返回主查询
----------------------------------------------------------------
```

**详细操作**:

##### 1. 车型筛选 (选项 1-3)
- `1`: 显示全部车型
- `2`: 仅显示高铁动车
- `3`: 仅显示普通车

##### 2. 站点筛选 (选项 4-5)

选择始发站或到达站时，系统会列出**所有可用车站**供选择：

```
【始发站列表】
========================================
 1. 广州   2. 广州白云   3. 广州东  4. 广州新塘
 5. 广州北
...
输入序号选择（按回车跳过）:
```

- 输入车站对应的序号即可选择
- 按回车键跳过，表示"全部"不进行筛选

##### 3. 时段筛选 (选项 6-0)
- `6`: 全部时段
- `7`: 00:00-06:00
- `8`: 06:00-12:00
- `9`: 12:00-18:00
- `0`: 18:00-24:00
对于争议比较大的，06:00归入06:00-12:00时段，12:00归入12:00-18:00时段，18:00归入18:00-24:00时段。此外，这个时段是发车的时段，不是到达时间的时段。
**注意：** 目前已知在识别运行图调整的车次时，到发时间会显示错误的问题。

##### 4. 排序功能 (选项 A-F)
- `A`: 按发车时间升序（最早发车）
- `B`: 按发车时间降序（最晚发车）
- `C`: 按到达时间升序（最早到达）
- `D`: 按到达时间降序（最晚到达）
- `E`: 按历时升序（最短历时）
- `F`: 按历时降序（最长历时）

##### 5. 其他操作
- `R`: 重置所有筛选条件
- `X`: 返回主查询界面

## 五、配置说明

### （一）修改配置 (菜单选项 2)

进入配置修改菜单，可以调整以下参数：

1. **切换DC识别模式** (当前: official)
   - `official`: D/C字头全归为高铁动车
   - `smart`: D/C字头1-899归为普通车
> 加入该功能是国铁对于D和C字头低号段的识别有些混乱，当然这里并不是反对垃圾桶，只是查询车票的时候方便一点

2. **修改智能识别阈值** (当前: 899)
   - 最好不要动（我也不知道为啥AI要这么整出一个配置，算了后续再改罢）

3. **修改通知冷却时间** (当前: 300秒)
   - 避免频繁发送通知

4. **设置仅监控目标车次** (当前: 否)
   - 仅对指定车次发送通知

5. **修改最小余票数量** (当前: 1)
   - 达到此数量才发送通知

### （二）通知设置 (菜单选项 4)
